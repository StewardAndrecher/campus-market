# 面试演示与发布说明

## 3 分钟演示路线

使用本地隔离数据库和虚构账号，不使用真实用户、真实支付或生产凭据。

1. **30 秒：业务闭环**
   - 打开首页，展示校区/分类筛选和商品详情。
   - 用买家账号创建订单，展示商品、价格和买卖双方快照。
2. **45 秒：一致性与幂等**
   - 重复提交同一请求标识，说明如何恢复原订单而不是重复占用商品。
   - 修改商品版本后再次提交，展示冲突提示；说明商品→订单的统一加锁顺序。
3. **45 秒：可靠消息与缓存**
   - 展示 Outbox、RabbitMQ 投递/消费记录及数据库超时补偿。
   - 说明商品详情的版本缓存、事务提交后失效、TTL 抖动和 Redis 故障降级。
4. **30 秒：售后与权限**
   - 展示交付/收货时间线和退款申请；强调“同意申请”不等于真实退款到账。
   - 用非订单参与者访问订单详情，展示接口级权限校验。
5. **30 秒：工程质量**
   - 展示 GitHub Actions、测试范围、10 万合成数据 SQL 测量和浏览器 E2E。
   - 主动说明模拟支付、本地部署、移动端真机和公网验收边界。

录制时建议采用 1440×900 浏览器窗口；提前准备买家、卖家两个隔离账号和一件演示商品。不得展示 `.env`、数据库密码、会话令牌、真实邮箱或个人信息。

## 发布前可执行检查

```sh
python3 scripts/dev.py deps
python3 scripts/dev.py backend
cd campus-market-client && sh tools/build.sh h5
cd e2e && npm test
```

完整 Java/Node 回归仍使用 `docs/GETTING_STARTED.md` 中的固定入口。E2E 只能在可丢弃的本地数据库上运行。

## 公网部署的真实边界

仓库提供生产配置、数据库权限分离、备份恢复和发布检查模板，但**当前没有宣称已经部署生产环境**。公网上线仍需实际完成并记录：

- 云主机、域名、HTTPS、反向代理与可信来源配置；
- 独立迁移账号和运行账号、密钥管理、日志轮转与告警接收人；
- 图片对象存储、异地加密备份、恢复演练和 PITR 策略；
- 真实商户支付、验签回调、原路退款与对账（如决定接入）；
- 浏览器兼容矩阵、核心 E2E、压力测试、小程序/App 真机验收。

具体配置入口见 `campus-market-server/release/deployment/PUBLIC-LAUNCH.md`。外部条件未完成时，只能写“提供部署模板”，不能写“已生产上线”。
